The Typical WebSocket Handler

In most frontend projects, handling WebSocket messages turns into an ever-growing block of imperative code: 

// The typical anti-pattern:
socket.onmessage = (event) => {
  try {
    const msg = JSON.parse(event.data);
    if (msg.type === "state") {
      updateDisplay(msg.data);
    } else if (msg.type === "announcement") {
      playAudio(msg.audio);
    } else if (msg.type === "error") {
      showError(msg.error);
    } else if (msg.type === "ping") {
      socket.send(JSON.stringify({ type: "pong" }));
    }
  } catch (err) {
    console.error("Message parse error", err);
  }
};

As the app grows, this handler becomes a dumping ground mixing networking, JSON serialization, message routing, and UI manipulation in one monolithic file.
